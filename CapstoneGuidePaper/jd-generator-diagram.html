AI Job Description Generator

Layer 1 and Layer 2 are this project's own TF-IDF matching and compliance rules — they run every time, for free, offline. Layer 3 (Gemini) is not decoration on top of them: it runs exactly when Layer 1 has nothing to retrieve — a job title with no similar posting yet in the database. That's the one gap the system's own data can't fill.

Layer 1 — own ML (TF-IDF + cosine) Layer 2 — own rules (compliance + guardrail) Layer 3 — Gemini (cold-start handler, runs only when Layer 1 is empty)

Gemini's role across the system

One rule, four places — own data/ML first, Gemini only for the gap it leaves. Not just this generator, and not just FAQs (§6.3).

FeatureOwn ML / data tried firstGap Gemini fills
JD Generator TF-IDF retrieval against existing MR.DIY postings Cold start — no similar posting exists yet
Resume Validator Trained binary classifier (Logistic Regression / Naive Bayes + TF-IDF) Low confidence — the local model isn't sure
Document verification (planned) — no automated check exists today The whole task — no vision/OCR model of our own, always guardrailed
FAQ assistant (planned) Existing job/requirement data as context Free-text questions — not a structured query a database can answer directly
